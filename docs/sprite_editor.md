# `tools/sprite_editor.html` — редактор координат спрайтов brush

Локальный визуальный редактор координат спрайтов brush. Входной файл — `metadata.xml` из
распаковки `bbrusher.exe unpack`. Цикл: `bbrusher.exe unpack` → редактор → `bbrusher.exe pack`
(проверено: pack/unpack координаты не теряет; offsetX="0" пакер сам отбрасывает).

## Основной вход и привязка PNG → кисть

- Сборка куклы (голова+тело+прочее) на белой сцене из общего pivot; drag/стрелки/поля для
  left/right/top/bottom/offsetX/offsetY; запись изменений обратно в metadata.xml.
- Основной вход — «Открыть PNG…»: 1-й диалог PNG, 2-й диалог ЕГО xml-файл (handle даёт координаты
  И запись при сохранении; картинка из PNG; левая панель показывает ТОЛЬКО открытое).
- Привязка png→кисть (pngMap + сверка по ВСЕМ загруженным xml) — строго по ИМЕНИ ФАЙЛА картинки
  (basename img), НЕ по id спрайта: id в brush может не совпадать с именем файла (напр.
  id="bust_head_615" img="entity\heads\bust_head_wushi_02.png" — резолв через img). Индекс
  brush.imgByBase перестраивается и при refreshBrushFromDisk.
- Диалог xml появляется, только если картинка не найдена ни в одной загруженной кисти (textHasImg).
- При каждом совпадении кисть перечитывается с диска (refreshBrushFromDisk; объекты спрайтов
  обновляются на месте, stage не ломается; если по кисти есть несохранённые правки — свежее НЕ
  подтягивается).
- Файловые диалоги стартуют в папке последнего выбора (startIn = lastPickerLoc, только сессия).
- Кисти от разных модов живут независимо, dirty/buildXml/save раздельные (id могут совпадать!);
  drag&drop xml+PNG — без записи на диск.

## Слои и отрисовка

- Z-градация: тело куклы 0 → доспех 10 → улучшение _back 20 → голова куклы 30 → шлем 40 →
  _front/прочее 60.
- Слой детали (шлем/доспех/улучшение/оружие) — авто (`armor_up` проверять РАНЬШЕ `armor`) +
  ручной; слой — ВИЗУАЛЬНЫЙ (только z-порядок, НЕ двигает спрайт, в XML не пишется; snap-механика
  удалена целиком).
- Радиокнопки «шлем/доспех/...» — ВИЗУАЛЬНЫЙ СЛОЙ (авто-угадывание по имени — лишь стартовое
  значение слоя). Кнопка «На куклу» УДАЛЕНА (не востребована).
- Ресайз: тянуть жёлтую границу выделенного спрайта (edgeHit 6px, resizedRect — визуальный верх =
  мировой b, кламп мин. размера 1px).
- Кнопки «Копир./Вставить коорд.» переносят шесть координат между вариантами спрайта.

## Координаты и запись в XML

- У части спрайтов в brush края rect'а опущены (только left+top+bottom и т.п.) — отсутствующие
  края ВЫВОДЯТСЯ из размеров PNG (spr._pngW/_pngH при загрузке картинки): оба отсутствуют ->
  центр на anchor'е, один -> известный ± размер PNG.
- Правки (drag/поля/nudge) пишут display-rect целиком — недостающие атрибуты материализуются в XML
  и добавляются в spr.present (иначе выводка из PNG продолжит их игнорировать — спрайт «не двигается
  по горизонтали»).
- Запись в XML — setCoordAttr: замена на месте (порядок атрибутов сохраняется), дубли вырезаются,
  парсер при загрузке читает ПОСЛЕДНЕЕ значение дубля.
- «Сбросить» откатывает координаты и spr.present (snapshot origPresent).

## Куклы и тайл

- Куклы по чекбоксам (живая/_dead) — `tools/assets/doll_*.png` (ванильные bust_naked_body_00 +
  bust_head_02, НЕ коммитятся, локальные).
- Чекбокс «тайл» — кукла для статичных объектов: `tools/assets/tile_grass.png` (terrain
  tactical_tiles grass_01) центрируется на pivot, объекты object_1 anchor'ятся в его центре —
  подгонка не нужна.

## i18n

- Словари в `tools/assets/lang_ru.js` / `lang_en.js` (registerLang(code, dict), подключаются ДО
  основного скрипта; ключи — t("key", {param})). Новые пользовательские строки — В ОБА словаря.
- Язык по УМОЛЧАНИЮ — английский (localStorage bbse_lang, null -> en). Переключатель RU/EN в
  шапке (reload). Статика — data-i18n / -tt / -ph.
- ЛОВУШКА: глобальная функция t() — не называть локальные переменные `t` (деструктуризация
  rect'а [l, t, r, b] затеняет и падает с "t is not a function").

## Уроки

- **buildXml (была бо-бага):** regex из строки с `\\s` матчил буквальную `\s` → замена молча
  падала и координаты ДОПИСЫВАЛИСЬ дублем (XML берёт первое значение — правки не применялись).
  Лечение: `rebuildCoordsInTag` вырезает ВСЕ координатные атрибуты тега и пишет один канонический
  набор (только для dirty-спрайтов; id могут содержать ПРОБЕЛЫ — `"...wushi_ armor16..."`). Дубли
  при загрузке авто-детектятся (parseBrush) и помечаются dirty — одно сохранение чистит файл.
- **Формат координат brush (проверено рендером портрета):** все bust-спрайты висят на ОДНОМ
  anchor'е, мировая ось Y вверх; мировой rect спрайта = (left+offsetX, top+offsetY, right+offsetX,
  bottom+offsetY), PNG ставится в него без поворота (визуальный верх картинки = мировой
  bottom+offsetY). Y-вниз/«вычитание offset» даёт перевёрнутую куклу — НЕ использовать.
