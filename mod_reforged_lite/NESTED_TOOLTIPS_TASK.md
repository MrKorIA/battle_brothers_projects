# Задача: ссылочные (вложенные) тултипы для ВСЕЙ игры

> Файл контекста для новой сессии. Сначала читать `AGENTS.md` этого мода (базовые принципы lite),
> затем этот файл. Проект: `mod_reforged_lite` (lite-версия Reforged), репозиторий
> `Z:\GameMods\Battle Brothers\mods\battle_brothers_projects`.

## Постановка проблемы

Игрок хочет, чтобы вложенные тултипы (гиперссылки `[текст|Concept.X]` / `[текст|Skill+имя]`
внутри описаний навыков, предметов, эффектов) работали **во всех текстах игры** — ванильных
и всех установленных модов — как в полном Reforged. Сейчас ссылки есть только в текстах
самого `mod_reforged_lite` (драугры, травмы, кризисные юниты, предметы Reforged).

## Что уже сделано (инфраструктура — НЕ переделывать)

- Зависимость: **mod_nested_tooltips 0.5.4** (полная версия с JS) установлен в data игры.
  Это его файлы, НЕ дублировать в lite (раньше была встроенная копия — удалена из-за конфликтов).
- API для текстов мода: `::ReforgedLite.Mod.Tooltips.parseString("[текст|Concept.X]")`
  (аддон MSU нашего мода; типы Skill/Item/Perk/Entity/Obj и т.д. — из mod_nested_tooltips).
- Хелперы генерации ссылок: `mod_reforged_lite/tooltips/nested_helpers.nut`
  (неймспейс `::ReforgedLite.NestedTooltips`: getNestedSkillName/Image, getNestedPerkName, ...).
- Concept-словарь мода: `mod_reforged_lite/tooltips/concepts.nut` — **минимальный**, только
  термины текстов lite-контента (~20 концептов + автоконцепты character-stats.*).
- Правило архитектуры (из AGENTS.md мода): скиллы/предметы НЕ хукаются поодиночке ради ссылок —
  `[текст|Skill+имя_файла]` резолвится через глобальный индекс ВСЕХ скиллов/предметов
  (vanilla + все моды) по имени файла скрипта.
- JS-хук проброса entityId в тултипы статов (п.6 изначальной задачи) работает.

## Почему ссылок нет в ванили и чужих модах

Ванильные тексты не содержат разметки. Полный Reforged добился ссылок ВЕЗДЕ, потому что
**физически переписал сотни ванильных файлов** (`mod_reforged_core-0.9.3-russian/scripts/...`
содержат хуки ванильных классов с `::Reforged.Mod.Tooltips.parseString`). Для lite это
**неприемлемо**: перезапись ванильных скриптов конфликтует с bb_vanilla_plus и любыми модами
(правило «бережно к ваниле»). Решение должно быть хуко-ориентированным.

## Варианты решения (обсуждены, НЕ выбран — решать в новой сессии)

**А. Словарная автозамена (рекомендовано пользователю как наиболее lite-совместимое).**
Один-два хука `getTooltip` (hookTree на `scripts/skills/skill`, опционально `scripts/items/item`
и эффекты): на выходе прогонять `text` каждой записи через словарь терминов и оборачивать
найденное в `[термин|Concept.X]`.
- Плюсы: ноль правок чужих файлов; работает для ванили И всех модов автоматически;
  соответствует правилу «ванильный вариант + хук».
- Минусы/риски: ложные срабатывания (короткие термины внутри других слов, словоформы);
  производительность (getTooltip вызывается часто — нужен кэш/быстрый префиксный поиск);
  тексты уже содержат BBCode `[color=...]` и закодированные цифровые теги nested tooltips —
  словарь НЕ должен матчиться внутри них.

**Б. Гибрид:** словарь для простых частотных терминов + ручные хуки getTooltip для сложных
мест (как сейчас tooltip_events у stats-модуля).

**В. (отвергнуто)** перенос текстовых правок ванили из reforged core — конфликты модов.

## Технические зацепки для реализации

- Полный Concept-словарь оригинала (~40 концептов с русскими текстами) —
  `Z:\GameMods\Battle Brothers\mods\!project\mod_reforged_core-0.9.3-russian\mod_reforged\msu_systems\tooltips.nut`
  + авто-концепты character-stats (там же, AutoConcepts). Можно переносить тексты целиком
  (заменив `::Reforged.Mod.Tooltips.parseString` → `::ReforgedLite.Mod.Tooltips.parseString`).
- Референс словаря-автозамены в BB-модах: искать `regexReplace`/`parseString`-wrapper'ы
  (например, у Reforged хуки `scripts/skills/skill.nut` в `mod_reforged/hooks/`).
- Хуки ванильных классов применять через `::ReforgedLite.HooksMod.hookTree(...)` в
  `mod_reforged_lite/hooks/**` (подхватываются `includeFiles` в load.nut).
- Склонения/морфология: словарь может хранить несколько форм одного термина
  («ход», «хода», «ходу» → Concept.Turn). Русские тексты — основная сложность.
- Проверка результата: игровой запуск (лог `C:\Users\Ivan\Documents\Battle Brothers\log.html`),
  наведение на ванильный навык (например, «Щит» у братца) — должно появиться подчёркивание.

1. Ссылки в текстах САМОГО lite работают? — РАЗРЕШЕНО: пайплайн parseString→JS работает

   что у полного Reforged). «Мёртвые ссылки» объяснялись другим: на тактической карте

   Reforged actor_tooltip_functions, extraData entityId:ID — резолв на конкретном актёре).
2. Какой вариант решения выбираем (А/Б)? — НЕ А/Б: пользователь выбрал перенос «как в
   Reforged» — хуки ванильных скиллов из mod_reforged/hooks/skills/**, только тултип-части,
   баланс НЕ трогаем. Правила переноса закреплены в AGENTS.md мода (раздел «Ссылочные
   тултипы навыков»). Первый батч: ~125 хуков в hooks/skills/** (vanilla skills).
3. Объём словаря — по факту ссылок перенесённых текстов (+Concept.MoraleCheck добавлен).
4. Предметы/контракты/события — не переносились (только скиллы + тактический тултип актора).
5. Кэширование автозамены — неактуально (словарная автозамена не используется).
