## Жёсткое правило API

**Запрещено выдумывать функции, константы и сигнатуры.** Каждое использование незнакомого метода/константы
сначала проверяется по источникам: распакованная ваниль `Z:\GameMods\Battle Brothers\mods\!project\data_014`
(grep по определениям) либо данный пользователем референс. Если подтвердить нельзя — не использовать,
а спросить или перестроить решение на проверенном API. Проверенные ловушки (полный список — в
`docs/locations/tactical_location_guide.md`): `Const.EntityType.Donkey` не существует (есть `CaravanDonkey`);
у тайла нет `hasObject()`; скилловый `onDamageReceived(_attacker, _damageHitpoints, _damageArmor)` ничего
не возвращает; у `CombatInfo` обязателен `TerrainTemplate`; `fillVisibility(Player, true)` — отключение
тумана войны; `Navigator().teleport()` в фазе развёртывания — мёртвая блокировка (игрока расставлять
`addEntityToMap`, паттерн tutorial_contract); **Squirrel BB не поддерживает битовые составные присваивания** (`|=`, `&=`, `^=`, `<<=`, `>>=`) — ваниль пишет `a = a | b`, иначе парсер падает с «expression expected»); мод `mod_useful_pack` (`mod_crisis_duration_setting`) полностью переписывает `updateGreaterEvil` на уровне инстанса — классовые хуки на него молча в тени; лечится мягкой сортировкой `queue(">mod_crisis_duration_setting", ...)` + обёрткой через `mods_hookNewObject` (хуки применяются к инстансу в порядке регистрации, см. `mod_hooks/!!redirect.nut`), реакции на смену состояния — хуком `update` + флаги `World.Statistics.getFlags()`); обёртки modern hooks обязаны повторять сигнатуру оригинала включая параметры по умолчанию (`function update(_ignoreDelay = false)`, а не `update()`), иначе падение «fewer total parameters» при загрузке.

## Инструменты

- `tools/sprite_editor.html` — локальный визуальный редактор координат спрайтов brush (файл
  `metadata.xml` из распаковки `bbrusher.exe unpack`): сборка куклы (голова+тело+прочее) на белой
  сцене из общего pivot, drag/стрелки/поля для left/right/top/bottom/offsetX/offsetY, запись
  изменений обратно в metadata.xml. Основной вход — «Открыть PNG…»: 1-й диалог PNG, 2-й диалог
  ЕГО xml-файл (handle даёт координаты И запись при сохранении; картинка из PNG; левая панель
  показывает ТОЛЬКО открытое). Привязка png→кисть (pngMap + сверка id по ВСЕМ загруженным xml):
  диалог xml появляется, только если спрайт не найден ни в одной загруженной кисти. При каждом
  совпадении кисть перечитывается с диска (refreshBrushFromDisk; объекты спрайтов обновляются на
  месте, stage не ломается; если по кисти есть несохранённые правки — свежее НЕ подтягивается).
  Файловые диалоги стартуют в папке последнего выбора (startIn = lastPickerLoc, только сессия). Кисти от разных модов живут независимо,
  dirty/buildXml/save раздельные (id могут совпадать!); drag&drop xml+PNG — без записи на диск.
  Отрисовка с z-градацией: тело куклы 0 → доспех 10 → улучшение _back 20 → голова куклы 30 →
  шлем 40 → _front/прочее 60. Тип детали (шлем/доспех/улучшение/оружие) — авто (`armor_up`
  проверять РАНЬШЕ `armor`) + ручной; ручная смена типа ВСЕГДА снапит ТОЛЬКО этот спрайт «на
  куклу» (snap [dx,dy] на элементе сцены, в XML НЕ пишется). Координаты: у части спрайтов в brush
  края rect'а опущены (только left+top+bottom и т.п.) — отсутствующие края ВЫВОДЯТСЯ из размеров
  PNG (spr._pngW/_pngH при загрузке картинки): оба отсутствуют -> центр на anchor'е, один ->
  известный ± размер PNG. Правки (drag/поля/nudge) пишут display-rect целиком — недостающие
  атрибуты материализуются в XML и добавляются в spr.present (иначе выводка из PNG продолжит
  их игнорировать — спрайт «не двигается по горизонтали»), заодно обнуляется snap элемента
  (иначе snap двоится: координаты+snap). Запись в XML — setCoordAttr: замена на месте (порядок
  атрибутов сохраняется), дубли вырезаются, парсер при загрузке читает ПОСЛЕДНЕЕ значение дубля.
  «Сбросить» откатывает координаты, spr.present (snapshot origPresent) и snap. Куклы по чекбоксам
  (живая/_dead) — `tools/assets/doll_*.png` (ванильные
  bust_naked_body_00 + bust_head_02, НЕ коммитятся, локальные). Чекбокс «тайл» — кукла для
  статичных объектов: `tools/assets/tile_grass.png` (terrain tactical_tiles grass_01) центрируется
  на pivot, объекты object_1 anchor'ятся в его центре — подгонка не нужна.
- **i18n:** словари в `tools/assets/lang_ru.js` / `lang_en.js` (registerLang(code, dict), подключаются
  ДО основного скрипта; ключи — t("key", {param})). Новые пользовательские строки — В ОБА словаря.
  Переключатель RU/EN в шапке (localStorage bbse_lang + reload). Статика — data-i18n / -tt / -ph.
  ЛОВУШКА: глобальная функция t() — не называть локальные переменные `t` (деструктуризация
  rect'а [l, t, r, b] затеняет и падает с "t is not a function").
- Радиокнопки «шлем/доспех/...» — ВИЗУАЛЬНЫЙ СЛОЙ (только z-порядок, НЕ двигают спрайт, в XML не
  пишутся; авто-угадывание по имени — лишь стартовое значение слоя). Явный прыжок — только кнопка
  «На куклу» (snap элемента сцены, порог ≤3px — vanilla-спрайты не дёргаются). Кнопки «Копир./
  Вставить коорд.» переносят шесть координат между вариантами спрайта. Цикл:
  `bbrusher.exe unpack` → редактор → `bbrusher.exe pack`. Проверено: pack/unpack координаты не теряет
  (offsetX="0" пакер сам отбрасывает).
- **Урок buildXml (была бо-бага):** regex из строки с `\\s` матчил буквальную `\s` → замена молча
  падала и координаты ДОПИСЫВАЛИСЬ дублем (XML берёт первое значение — правки не применялись).
  Лечение: `rebuildCoordsInTag` вырезает ВСЕ координатные атрибуты тега и пишет один канонический
  набор (только для dirty-спрайтов; id могут содержать ПРОБЕЛЫ — `"...wushi_ armor16..."`). Дубли
  при загрузке авто-детектятся (parseBrush) и помечаются dirty — одно сохранение чистит файл.
- **Формат координат brush (проверено рендером портрета):** все bust-спрайты висят на ОДНОМ anchor'е,
  мировая ось Y вверх; мировой rect спрайта = (left+offsetX, top+offsetY, right+offsetX, bottom+offsetY),
  PNG ставится в него без поворота (визуальный верх картинки = мировой bottom+offsetY). Y-вниз/«вычитание
  offset» даёт перевёрнутую куклу — НЕ использовать.

## Сборка

- Общая реализация — в корневом `build.sh` (аргументы: `<имя.zip> [каталог мода]`, каталог игры
  можно переопределить через `BB_DATA`). В каждом моде остаётся только тонкий `build.bat`, передающий
  имя zip (см. реестр выше) и каталог мода в общий скрипт. ЗАПРЕЩЕНО запускать сборку
  автоматически — только по явной просьбе пользователя, при закрытой игре (иначе «Corrupted archive»).
- Скрипт упаковывает существующие игровые папки мода (brushes/gfx/music/scripts/sounds/ui + каталог хуков mod_*/zmod_*)
  и кладёт zip с заменой в `Z:\SteamLibrary\steamapps\common\Battle Brothers\data`.

## Правила ведения задач

- Текст коммита для вкладки Commit IDE ведём в `.commit-msg.txt` (в gitignore) в корне.
  Туда пишем только содержательное описание фичи/изменений. НЕ пишем туда самоликвидацию:
  то, что агент сам сломал и починил в рамках задачи (например, кавычки/слэши в bat-обёртках).
- Если что-то не получилось с первой итерации и этому есть чему учиться — урок заносим в правила
  (этот файл или профиль мода), а не в текст коммита.
- Запрещено запускать фоновых агентов (background agents) — работаем строго последовательно:
  один агент за раз, дожидаемся результата. Фоновые агенты на текущий момент нестабильны
  (отвалы по таймауту).
